MongoDB index re-test: 10 runs each with and without index, using hint({$natural:1}) to force a collection scan.

=== M1: Catalogue search (category=Men, size=M, colour=Black, stock_qty>0) ===

WITHOUT idx_variants_search (forced COLLSCAN via hint):
Run times (ms): 16, 7, 7, 5, 6, 7, 8, 16, 10, 7
Sorted:         5, 6, 7, 7, 7, 7, 8, 10, 16, 16
Median (avg of 5th+6th): (7+7)/2 = 7.0 ms
Docs examined: 1000

WITH idx_variants_search:
Run times (ms): 19, 8, 11, 7, 8, 7, 12, 7, 15, 10
Sorted:         7, 7, 7, 8, 8, 10, 11, 12, 15, 19
Median (avg of 5th+6th): (8+8)/2 = 8.0 ms
Docs examined: 198

Result: Time median is 8ms WITH vs 7ms WITHOUT — no time improvement (worse by ~14%).
But docs examined dropped from 1000 to 198 (-80%), well above the 50% threshold.
Decision: KEEP idx_variants_search. The time gain is not measurable at this data size
(1000 documents fit in memory). With a larger catalogue the index would prevent a
full scan on disk. Noted clearly per the rule.
